Upload PDF, DOCX, or TXT documents and ask an LLM questions grounded in your files (RAG).

## Architecture overview

- **Frontend:** Next.js 15 (App Router) + TypeScript + Tailwind — Login, Signup, Dashboard, AI Chat with SSE streaming.
- **Backend:** FastAPI — JWT auth, uploads, RAG ask/history, auto OpenAPI at `/docs`.
- **Database:** PostgreSQL 16 + **pgvector** for users, documents, chat history, and embeddings.
- **Queue / cache:** Redis + **ARQ** worker for async ingest; Redis cache for document lists.
- **AI:** Google Gemini (chat + `text-embedding-004`) via LangChain; chunk → embed → retrieve → generate.

```text
Browser → Next.js (Vercel)
           ↓ JWT Bearer
         FastAPI (Railway)
           ├─ Postgres + pgvector
           ├─ Redis (cache + ARQ queue)
           └─ ARQ worker → parse/chunk/embed
           └─ Gemini (RAG answers + embeddings)
```

## Local setup

### Prerequisites

- Docker Desktop (Postgres + Redis + optional full stack)
- Node 20+
- Python 3.12+ (or run API via Docker only)
- `GEMINI_API_KEY` from [Google AI Studio](https://aistudio.google.com/apikey)

### 1. Environment

```bash
cp .env.example backend/.env
# set GEMINI_API_KEY and JWT_SECRET in backend/.env

cp frontend/.env.example frontend/.env.local
# NEXT_PUBLIC_API_URL=http://localhost:8000
```

### 2. Start infrastructure + API

```bash
docker compose up --build
```

This starts Postgres (pgvector), Redis, API (`:8000`), and the ARQ worker.

Swagger: [http://localhost:8000/docs](http://localhost:8000/docs)

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

App: [http://localhost:3000](http://localhost:3000)

## Deployment instructions

### Backend (Railway)

1. Create a Railway project.
2. Add **PostgreSQL**. Connect with a shell and run: `CREATE EXTENSION IF NOT EXISTS vector;` (or use a pgvector template image if available).
3. Add **Redis**.
4. Deploy the `backend` service from this repo (Dockerfile). Set start command:

   ```bash
   alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT
   ```

5. Deploy a second service for the **worker** from the same Dockerfile:

   ```bash
   arq app.workers.settings.WorkerSettings
   ```

6. Attach a volume to `/app/uploads` for both API and worker (same mount).
7. Environment variables:

   - `DATABASE_URL` (use `postgresql+psycopg2://...` — replace `postgres://` if needed)
   - `REDIS_URL`
   - `JWT_SECRET` (long random string)
   - `GEMINI_API_KEY`
   - `CORS_ORIGINS` (your Vercel URL)
   - `FRONTEND_URL`
   - `UPLOAD_DIR=/app/uploads`

### Frontend (Vercel)

1. Import the GitHub repo in Vercel.
2. Root directory: `frontend`
3. Env: `NEXT_PUBLIC_API_URL=https://YOUR-RAILWAY-API.up.railway.app`
4. Deploy.

## Assumptions

- English documents; max upload 10MB.
- Users only query their own documents.
- Gemini is the sole LLM/embedding provider (`gemini-2.0-flash` + `gemini-embedding-001`).
- JWT access tokens are stored in `localStorage` (Bearer header) for SPA simplicity.
- If Gemini `generateContent` quota is exhausted (HTTP 429), the API falls back to an extractive answer from retrieved chunks so demos still work. Embeddings still require a working Gemini key.
- Local Docker Postgres is mapped to host port **5433** to avoid clashing with Homebrew Postgres on 5432.

## Trade-offs

- **pgvector vs Pinecone/Chroma:** one database, simpler ops; ANN tuning is DIY.
- **Gemini vs OpenAI:** lower cost for demos; quality trade-off on hard reasoning.
- **ARQ vs Celery:** lighter asyncio stack with FastAPI.
- **localStorage JWT vs httpOnly cookies:** faster to ship; slightly higher XSS risk mitigated by avoiding inline scripts.
- **Volume-backed uploads vs S3:** cheaper for assignment; requires Railway volume.
